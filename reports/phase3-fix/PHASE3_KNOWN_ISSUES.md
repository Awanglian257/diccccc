# 第三阶段第二轮：剩余问题与边界

本轮未调用真实 DeepSeek API，未发布或推送代码。

| ID | 状态 | 级别 | 说明 |
|---|---|---|---|
| K01 | OPEN | P2 / 接口兼容 | 为保持现有 79 项测试和旧调用方协议，`Orchestrator.confirm()` / HTTP `/confirm` 未选择 `defer_commit` 时仍表示“计算及授权流程完成”，返回 `requires_local_commit=true`、`persistence_status=not_requested`；这不是持久化成功证明。所有本次页面保存入口显式使用两阶段确认。独立调用方必须迁移，不能只看 `status=completed`。本轮没有宣称所有旧客户端已迁移。 |
| K02 | OPEN | P2 / 恢复能力 | 后端 session、任务和草稿仍是内存对象；服务重启、会话过期或刷新后无法恢复原有远程任务。已本机提交的数据和回执保留；刷新显示 `local_persisted / ACK_INTERRUPTED`，不能伪称服务器已恢复。尚未引入服务端数据库。 |
| K03 | OPEN | P2 / 并发边界 | 本机 Agent 确认通过 Web Locks 串行化，单页有防重复锁，提交前后检查快照。localStorage 日志提供本应用读取视图及失败恢复，不是浏览器原生多键事务。旧版页面、外部脚本直接读写 localStorage、未遵守锁的其他标签页，不具备数据库级全局可串行化保证。 |
| K04 | BLOCKED | 环境 | Firefox、WebKit 二进制未安装，第二阶段独立验收各保留一项 BLOCKED；当前真实浏览器验证为系统 Chromium。 |
| K05 | SKIP | 本轮明确禁止 | 未再次调用真实模型；无法证明真实 Token 或费用下降。缓存收益仅来自明确标注的离线模拟上游和确定性营养工具。 |
| K06 | OPEN | 存储约束 | 日志保存写前/写后值，需要额外浏览器空间；配额不足会阻止提交并保留草稿。无法保证设备断电后的物理介质刷盘，也不恢复用户主动清空浏览器数据。 |

四个原始失败用例的页面路径均已修复并复测。以上边界仍须披露；不得把本轮结论扩大为“所有客户端、所有浏览器及跨进程数据库持久化均已完成”。
